I can tell you what my systems scored, and how I know the number is real.

The first thing I build is the way I'll know whether the rest of it works. On my last project that meant hand-labelling 233 questions before writing any retrieval code — deciding what a right answer looked like while I still had nothing invested in the outcome.

233

Questions, labelled by hand, then frozen. Nothing was tuned against anything else.

It is a slow way to begin and it has paid for itself every time. Retrieval accuracy on that project went from 44 to 97 out of 100 across six changes, and I can tell you which change did what, because each one was measured on its own and tested for significance rather than eyeballed. It also meant I had to decline a fifteen-point improvement that landed at p = 0.0534.

p = 0.0534

Just outside significance. I said so rather than claiming the fifteen points.

The same habit makes me throw work away. I spent real time fine-tuning SecureBERT for a URL classifier, then found it had learned shortcuts in the dataset rather than anything about URLs, and fell apart on domains it hadn't seen. What shipped instead was small enough to run inside the browser.

Grouped by domain, because URL datasets leak by host and ungrouped splits flatter you.

Selected work

Kural RAG Cross-lingual retrieval over classical Tamil

Answers plain-English questions from 1,330 classical Tamil verses and cites the specific verses behind every claim. Hybrid dense and sparse retrieval, cross-encoder reranking, and query rewriting to close the vocabulary gap between a modern question and a nineteenth-century translation.

How each gain was verified

McNemar's exact test on all six changes, measured independently

What I declined to claim

A 15-point gain at p = 0.0534 — reported as inconclusive

What a reader actually gets

78% a correct verse in five · 56% correct first

Clikk On-device malicious URL detection

On the Chrome Web Store. Screens links for phishing and malware before they open, with the classifier running on-device so most URLs never leave the browser. I audited the public training data against primary threat feeds, found mislabelled entries in a widely used dataset, and rebuilt the training set from scratch.

How it was evaluated

Domain-grouped splits — 98.6% accuracy at 0.3% false positives

What I threw away

A fine-tuned SecureBERT that had learned dataset shortcuts

Cost of running it

~0.2 ms per URL, offline, inside the browser
