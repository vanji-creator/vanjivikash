Clikk checks a link for phishing and malware before you click it. The classifier runs entirely on-device, so almost every URL is decided without leaving the browser. The interesting part is not the model that shipped — it is the one I threw away, and why I could prove that was the right call.

The model I discarded

I fine-tuned SecureBERT first, because that is what you reach for. It scored well and it was wrong. Audited properly, it had learned shortcuts in the dataset rather than anything about URL structure, and it degraded on domains it had never seen — which is the only condition that matters for a link scanner.

Evaluation is domain-grouped, so no domain appears on both sides of the split. URL datasets leak by host, and an ungrouped split flatters you.

Fine-tuned SecureBERTTF-IDF n-gram + logistic regression — shipped
What it learned Dataset shortcuts, not URL structure Character patterns in the URL itself
On unseen domains Degraded 98.6% at 0.3% FPR
Runs in the browser No Yes — offline, ~0.2 ms per URL

The shipped model is TF-IDF character n-grams of length three to five feeding a logistic regression, trained on roughly 26,000 engineered URLs with per-domain caps. It was chosen small on purpose, against real deployment constraints: it has to run offline inside a Manifest V3 service worker with zero dependencies. A transformer cannot meet that constraint; this model does.

"Suspicious" is a post-hoc probability band between 0.30 and 0.70, not a training label — so model uncertainty fails safe to be careful, never to a confident guess.

The dataset was poisoned

Auditing the public training data against primary threat feeds turned up label swaps at a scale that could not be noise, in a Kaggle dataset used across dozens of public notebooks. It is provable by arithmetic: almost all of its overlap with trusted feeds disagreed, and disagreed symmetrically.

48,009 / 47,903

Phishing relabelled benign, and benign relabelled phishing. A symmetric swap that large is not error — it is a corrupted file that a lot of people trained on.

I documented the forensics and rebuilt the training set from primary sources: URLhaus, OpenPhish and ThreatFox.

Proving the port was exact

The trained weights are exported to a 1.7 MB JSON artifact with a sha256 fingerprint, and inference is reimplemented in dependency-free JavaScript so it can live in the extension. A reimplementation that is nearly right is a silent bug, so it was checked rather than assumed: the Python and JavaScript pipelines were run against the full 5,249-URL test set and compared.

2 × 10⁻⁸

Worst probability difference across the whole test set. Zero verdict flips, identical confusion matrix. The model loads once in ~250 ms.

How a verdict is reached

The scan pipeline is layered so that almost all verdicts stay local, and each layer only hands on what it cannot decide:

  1. In-memory cache — one-hour TTL, so repeat verdicts return instantly.
  2. Local blocklists — URLhaus, OpenPhish and ThreatFox in IndexedDB, refreshed daily.
  3. Heuristics — India-specific scam patterns: fake KYC and UPI shapes, sketchy TLDs, deep subdomains.
  4. The on-device model — decides alone when it is at least 90% confident.
  5. VirusTotal — a network call only for the uncertain remainder, and only with your own key.

Privacy is a consequence of that ordering rather than a policy on top of it: no accounts, no analytics, telemetry off by default.
